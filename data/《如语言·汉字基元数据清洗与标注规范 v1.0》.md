《如语言·汉字基元数据清洗与标注规范 v1.0》

规范总则
1.1 目的
本规范旨在定义“如语言”输入法端侧AI模型训练数据的清洗、拆分、标注及质检流程。确保输入模型的训练集严格遵循《如语言构字基元 v7.1-Final 技术规格书》，实现“零特例、高置信度、低冗余”的数据标准。

1.2 适用范围
适用于“如语言”AI字形补偿模块的种子数据集构建、历史纠错日志清洗及增量数据标注。

1.3 核心原则
文化本体优先：所有部件拆分必须以传统书法笔顺及《说文解字》造字理据为准，严禁采用现代检字法的无理据拆分。
绝对同构：同一基元在不同汉字中的内部编码必须绝对一致（如：左耳旁“阝”与右耳旁“阝”统一标注为 R_FU）。
最小颗粒度：拆分必须达到29个基元或5个基础笔画的最小颗粒度，禁止保留未定义的复合部件。

数据清洗规则（Data Cleaning）
2.1 字符集过滤
仅保留 GB18030-2022 及 Unicode 14.0 标准内的汉字。
剔除生僻异体字、日韩汉字（Kanji/Hanja）、特殊符号及控制字符。
剔除笔画数大于30画的极端生僻字（避免占用极小模型宝贵的权重）。

2.2 脏数据清洗
去重：基于 Unicode 码位进行全局去重。
纠错：清洗因OCR识别错误产生的乱码、缺笔画字。
格式统一：全角/半角字符统一转换，去除不可见控制符。

基元标注规则（Annotation Rules）
3.1 基元映射表（强约束）
标注人员必须熟记并严格执行《29-Key Matrix》映射表。
五行基元：金、木、水、火、土（独立标注，不可拆解）。
基础笔画：横(S_H)、竖(S_S)、撇(S_P)、点(S_D)。注意：捺(Na)必须归一化为点(S_D)；折笔(Zhe)必须拆解为横竖撇点的组合。
核心偏旁：如“氵”必须标注为 W_S(水)，“扌”必须标注为 R_SHOU(手)。

3.2 拓扑结构标注
对于每个汉字，需按书写顺序输出基元序列，并附带空间拓扑标签：
左右结构：[Left] + [Right] （例：陈 = R_FU + W_M）
上下结构：[Top] + [Bottom] （例：杏 = W_M + R_KOU）
包围结构：[Outer] + [Inner] （例：国 = R_KOU + W_YU）

3.3 特殊部件处理（防特例机制）
阝（阜/邑）：无论左右，统一标注为 R_FU。空间位置由上下文拓扑标签决定，严禁在标注时区分“左耳旁”或“右耳旁”。
竹字头（⺮）：统一拆解为两个“个”字（S_P+S_H+S_D），作为AI补偿模块的重点训练对象。

数据标注格式（JSONL）
每条训练数据需包含以下字段：
{
  "char": "陈",
  "unicode": "U+9648",
  "component_seq": ["R_FU", "W_M"],
  "topology": "LR",
  "stroke_count": 7,
  "source": "manual_annotation"
}

质量控制与验收（QA & Validation）
5.1 交叉验证（Cross-Validation）
采用“双人盲标 + 第三人仲裁”机制。
同一批次数据，两人标注结果一致性（Krippendorff's Alpha）必须 ≥ 0.95。

5.2 自动化校验脚本
开发团队需提供自动化校验工具，对标注结果进行100%机审：
校验基元序列是否包含非法编码。
校验笔画总数是否与 stroke_count 匹配。
校验是否存在硬编码特例（如检测到 R_FU_LEFT 直接报错）。

5.3 验收标准
3500个常用字基元拆分准确率：100%。
扩展字库（10000字）基元拆分准确率：≥ 99.5%。
未达标批次一律打回重标。
