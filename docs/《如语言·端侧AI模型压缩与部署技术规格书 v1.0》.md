《如语言·端侧AI模型压缩与部署技术规格书 v1.0》

总则与适用范围
1.1 目的
本规格书旨在定义“如语言”输入法端侧AI字形补偿模块（Transformer-Lite）的压缩、量化及部署标准。确保最终交付的模型在满足 ≤10MB 内存占用与 <15ms 推理延迟的同时，保持 ≥98% 的首候选命中率。

1.2 适用对象
AI算法工程师、模型部署工程师、移动端开发工程师及QA测试工程师。

1.3 核心工程原则
精度-效率平衡：严禁采用“一刀切”的暴力压缩，必须采用混合精度与量化感知训练（QAT）以保障汉字拆解的准确率。
硬件亲和性：模型结构必须针对移动端NPU/GPU的并行计算特性进行算子融合与内存布局优化。
无损降级：压缩后的模型在3500常用字测试集上的性能衰减不得超过 1%。

模型压缩流水线（Compression Pipeline）
2.1 知识蒸馏（Knowledge Distillation）
教师模型（Teacher）：采用参数量 ≥300M 的全精度Transformer模型，在清洗后的基元数据集上全量训练，作为知识源。
学生模型（Student）：采用极小架构（如2层Transformer，隐藏层维度256），参数量控制在 10M 以内。
蒸馏策略：采用软标签（Soft Target）蒸馏。通过动态温度调节机制（Temperature Annealing），初期扩大概率分布范围以传递暗知识，后期聚焦精确预测，确保学生模型继承教师模型 95% 以上的拆解能力。

2.2 结构化剪枝（Structured Pruning）
重要性评估：基于动态滑动窗口监测，计算各注意力头（Attention Heads）的平均注意力得分与梯度更新稳定性。
精准裁剪：移除对输出影响 <0.1% 的冗余注意力头及前馈网络通道（目标裁剪率 30%-40%）。
约束：仅允许结构化剪枝，确保剪枝后的模型保持规则的矩阵结构，完美适配移动端硬件加速器。

2.3 极限量化（Quantization）
混合精度分配：输入层与输出层保持 FP16（半精度）以维持数值稳定性；中间核心隐藏层激进量化为 INT8 甚至 FP4。
量化感知训练（QAT）：禁止直接使用训练后量化（PTQ）。必须在训练过程中插入可学习的缩放因子（Scale Factor）并模拟INT8量化误差，使模型在带噪环境中微调，将量化精度损失控制在 1% 以内。
溢出保护：针对ARM架构处理器，必须开启“动态范围对齐”与量化溢出保护机制，防止突发性数值溢出导致推理中断。

端侧推理引擎优化
3.1 算子融合与内存优化
图级优化：将“矩阵乘法 + 激活函数 + 层归一化”等连续操作融合为单一算子，大幅降低内存带宽压力。
内存池管理：采用 LRU 策略管理模型分段，设定推理内存池上限（如 64MB），防止内存泄漏。

3.2 硬件加速适配
跨平台部署：Android端优先采用 NNAPI 或 TFLite 格式，iOS端转换为 CoreML 格式，充分利用 Apple Neural Engine (ANE) 或高通 NPU。
性能验收指标：
  单次拆解延迟：P95 ≤ 15ms
  内存峰值占用：≤ 25MB
  功耗控制：持续推理状态下，设备温升 ≤ 3°C

质量验收与回归测试
4.1 自动化基准测试
每次模型压缩或量化版本发布前，必须在标准测试机（如骁龙660级别低端机）上运行 3500字全量自动化回归测试。
若首候选命中率低于 98%，或单次拆解延迟高于 15ms，自动阻断发布流程。

4.2 异常排查机制
推理结果NaN：触发量化溢出保护，回退至 FP16 降级推理。
内存泄漏（OOM）：触发强制缓存清理机制（Unload Submodules）。
性能波动大：检测是否触发设备温度节流（Thermal Throttling），动态调整推理Batch Size。

版本管理与变更控制
本规格书为 v1.0 版本。任何对模型架构、量化位宽或蒸馏策略的修改，必须：
提交《模型压缩影响评估报告》及精度对比数据；
获得架构委员会批准；
版本号递增（如 v1.1 或 v2.0）。
